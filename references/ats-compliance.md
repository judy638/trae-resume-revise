# ATS 合规规范与校验清单

本文件定义简历的 ATS（Applicant Tracking System，简历追踪系统）合规标准。所有生成的简历必须通过以下校验，确保能被主流 ATS 系统正确解析。

## 什么是 ATS

ATS 是企业用来筛选简历的自动化系统，常见的有北森、Moka、大易、iCIMS、Greenhouse 等。ATS 通过解析简历文本内容，自动匹配岗位关键词、评分排序。如果简历格式不规范，可能导致：

- 关键信息识别失败（姓名、联系方式、工作经历等）
- 关键词匹配率低
- 简历评分偏低，直接被过滤

## ATS 合规黄金法则

### 1. 纯文本优先

- 所有内容必须是可选中的文字，不能是图片中的文字
- 头像不包含文字信息
- 图表用文字描述，不用图片
- 不要用文本框、形状等非标准元素

### 2. 结构清晰

- 使用标准的板块标题（如"工作经历""教育背景""技能"）
- 板块顺序符合常规阅读习惯
- 时间倒序排列（最新的在前）
- 每段经历结构一致（公司-职位-时间-描述）

### 3. 关键词充足

- 简历中包含目标岗位的核心技能关键词
- 关键词出现在正文文本中（不是图片或页眉页脚）
- 硬技能和软技能都要覆盖
- 关键词自然融入，不堆砌

### 4. 格式简洁

- 单栏布局优于多栏（多栏可能导致解析顺序混乱）
- 避免复杂的表格布局
- 使用标准字体（宋体、黑体、微软雅黑、Arial、Helvetica 等）
- 不用特殊符号或装饰性元素

## 校验清单

PDF 生成前必须逐项检查：

### 文本可读性
- [ ] PDF 中所有文字均可选中复制（非图片化）
- [ ] 姓名为纯文本，字号清晰
- [ ] 电话号码为纯文本，格式规范
- [ ] 邮箱地址为纯文本
- [ ] 地址/城市为纯文本

### 结构规范性
- [ ] 板块标题使用语义化标签（h2 或类似层级）
- [ ] 板块标题为标准名称（工作经历、教育背景、技能等）
- [ ] 工作经历按时间倒序排列
- [ ] 每段经历结构一致：公司 + 职位 + 时间 + 描述
- [ ] 经历条目使用列表结构（ul/li）

### 布局安全性
- [ ] 单栏布局（无多栏）
- [ ] 无文本框、形状、SmartArt 等复杂元素
- [ ] 无页眉页脚中的关键信息（ATS 可能忽略页眉页脚）
- [ ] 分页不打断单条经历（条目完整）
- [ ] 左右边距充足（≥ 1.5cm）

### 关键词覆盖
- [ ] 目标岗位的硬技能关键词在简历中出现
- [ ] 目标岗位的软技能关键词在简历中出现
- [ ] 行业关键词在简历中出现
- [ ] 关键词出现在正文（不在图片、页眉、页脚）
- [ ] 关键词自然融入，不堆砌

### 价值审计通过
- [ ] 每段经历命中至少 3 个价值维度
- [ ] 关键经历（最近 2 份工作）命中 ≥ 4 个价值维度
- [ ] 每条经历描述包含具体成果或影响
- [ ] 无纯职责描述无成果的条目

### 字体与格式
- [ ] 使用标准中文字体（PingFang SC / 思源黑体 / 微软雅黑）
- [ ] 使用标准英文字体（Arial / Helvetica）
- [ ] 正文字号 ≥ 10pt
- [ ] 标题字号 ≥ 12pt
- [ ] 行间距 ≥ 1.2 倍

## 常见 ATS 不友好的做法（避免）

❌ **图片简历**：整个简历是一张图片，ATS 完全无法读取
❌ **创意简历**：大量图形、图标、装饰，干扰解析
❌ **双栏/多栏**：ATS 可能从上到下逐行读，导致左右栏内容错乱
❌ **表格布局**：表格可能被逐格读取，顺序混乱
❌ **页眉页脚信息**：很多 ATS 忽略页眉页脚，关键信息放这里等于没写
❌ **特殊字体**：ATS 可能无法识别艺术字体或稀有字体
❌ **二维码**：ATS 无法解析二维码内容
❌ **缩写不展开**：只写缩写可能导致关键词匹配失败（如"SEM"最好同时写"搜索引擎营销(SEM)"）

## 关键词优化技巧

### 关键词从哪里来
- 岗位描述中的"任职要求"和"岗位职责"
- 行业通用技能词
- 公司官网/招聘页面的高频词
- BOSS/猎聘等同岗位 JD 的高频词

### 关键词怎么放
- 硬技能放在"技能"板块，分类清晰
- 软技能融入经历描述中，用行动体现
- 行业关键词自然融入个人优势和经历
- 避免关键词堆砌（同一词出现 5 次以上可能被判作弊）

### 关键词密度建议
- 核心硬技能：出现 2-3 次（技能板块 + 经历中各一次）
- 软技能：出现 1-2 次（融入经历描述）
- 行业词：出现 2-3 次（个人优势 + 经历中）
